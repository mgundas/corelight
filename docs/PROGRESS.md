## Decisions made during development

- M00 review fixes: `World.nextId()` (seed + per-world counter) is the only ID source in sim paths (`applyAction`); `newId()` is UI-only and counter-based (no `Date.now`/`Math.random`) to keep same-seed replays identical. `Renderer.applyOriginShift` skips `THREE.Light` objects and re-pins the sun to a fixed direction so origin shifts never change lighting. Placeholder sphere detail 24 -> 5 (detail 24 = ~5e15 tris, hangs the tab).
- M02 solid-skip deviation: ARCH's "certainly all solid" corner+center check is unsound for our density — tunnel walls are cliffs (d -> 0- inside, ~= depth+relief outside), so a worm thinner than the sample spacing reads solid at all 9 points (regression test pins a seed-1337 case). The streamer and boot only pre-skip 'air' verdicts (proven sound: large-magnitude negative density only occurs in the continuous above-ground field); everything else is decided exactly by the worker's full-grid sampling.
- M02 origin-shift fix: `applyOriginShift` moved `chunks.group` (meshes are re-synced absolutely), which double-shifted all terrain after flying >1000 m. Groups that position children from world doubles now set `userData.originManaged` and are skipped; chunk bounds resync from stored world boxes.
- M02 drain-before-recompute: applying finished jobs before diffing avoids re-queueing jobs that already completed (was doubling every submission).
- M03 Rapier queries need `world.step()` every tick: without it the broadphase stays stale and `computeColliderMovement` falls through the floor. Step only refreshes queries in M03 (no dynamic bodies yet), deterministic at fixed dt.
- M03 collider data is a separate path, not reused mesh buffers: new `colliderWorker` (marching cubes, no skirts/colors) + `ColliderPool`, sharing `terrain/sampleGrid.ts` with the mesh worker so visual and collision surfaces sample the identical grid.
- M03 embedded safety freezes instead of falls: fully-solid L0 chunks produce no trimesh (no surface), so a buried player must skip gravity/controller integration and only push out along the inverse gradient (depth-scaled, capped per tick), else the fall velocity outruns the push.
- M03 ring always requests the containing L0 chunk even past the 48 m filter: `groundState` depends on it, and a player dropped from high above learns "all air, keep falling" (empty -> ready) instead of freezing on an unrequested chunk. Ring range clamps into the octree root.
- M03 boots into third-person (fly default-off; F3 still toggles, exiting fly teleports the player to the camera). PlayerInput handlers are gated by mode so fly keys never leak into the rig.
- M03 review fixes: camera collision queries nearby Rapier LOD0 terrain colliders directly (`TerrainColliders.castTerrainRay`) instead of traversing render meshes; pure orientation/basis helpers live in `frames.ts`; deep space reports `ready` because there is no terrain chunk to wait for (directed space motion stays out of scope); all astronaut materials are disposed.
- Cavern floors: `cavernStack` derives floor count from planet size (Sela: usable 324 m / 46 m pitch = 7 floors, fit above the core shell). Rooms are local pockets, not global shells (`smoothstep` blotch mask + one golden-angle anchor pocket per floor so no floor is barren near the play area); the mask pinches ceilings shut where closed, preserving mid-cell crossings. Floors are walkable relief with capped pits; slabs stay ~88% solid with rare worm-pierced openings (`openingBoost` 0.25). (The old safety-test burial point landed in room 0, which forced the safety-net hardening described below.)
- FIX cave shreds: the carve now applies unconditionally as `min(d, (c-threshold)*10)`, exactly matching the ARCH density formula (the code had an `if (c < threshold)` guard). The guard pitted +depth against ~0 at worm walls so every crossing hugged a grid point (measured: 279/279 wall crossings at t<0.1 or t>0.9 in a seed-1337 cave chunk); the unconditional form puts both sides on the carved branch, centering crossings and smoothing central-difference normals. Zero set, signs, and the negative field are identical, so air-skips, spawn, and collider surfaces are unaffected. Side effect: deep-rock reads are small-positive now, so `classifyNode` can no longer report false 'solid' near worms (only air-skips were ever trusted) and the embedded safety gained gradient-flat-spot fallback plus sticky surface-ward escape after `EMBED_ESCAPE_S`.
- FIX walk jitter + terrain seams: the orbit camera and the astronaut now share one interpolated render transform (`PlayerView.interpolatedWorld`), instead of the camera following raw post-tick sim state while the mesh rendered a lagged interpolation; terrain material uses smooth vertex normals (`flatShading: false`) so facets and LOD-boundary shading steps soften. This narrows the old "flat-shaded everything" look to props/character only (docs updated).
- M04 applySphere signature deviation: the prompt lists `applySphere(planetId, center, radius, strength, mode)`, but planetId alone cannot locate chunks (needs rootMin/lodMaxLevel) and soil/hardness accounting needs the base density, so it takes `(planet, density, center, radius, strength, mode, opts)` with optional hardness/flatten params. Soil/hardness stay inside TerrainEdits so all edit math is unit-tested in one place; applyAction only wires the player and the planet.
- M04 collider-swap deviation: the prompt's "treat missing/updating colliders as solid for 1 frame" is implemented as ghost colliders + atomic swap. The old collider stays until fresh data with a matching edit version arrives (same tick it lands), so the player stands on at most ~100 ms stale ground and can never fall into a half-updated hole; groundState 'pending' freeze only applies when no collider exists at all (e.g. adding soil where there was only air).
- M04 LOD1 parents: notifyEdited queues the LOD0 keys plus their LOD1 parents (averaged edits); LOD2+ ignore edits per ARCH. Stale in-flight jobs are dropped by version and refreshed, never flashed.
- M04 review fixes: (1) all files back under 400 lines — edit-remesh ownership moved to `terrain/editRemesh.ts`, sink/frustum/stats to `terrain/streaming.ts`, job-grid resolution to `terrain/editDeltas.ts`, aim math to `player/toolAim.ts`, edit plumbing to `game/editWiring.ts`. (2) Neighbor fan-out replaced with an exact rule: only chunks whose 35^3 window contains a touched sample remesh (mid-brush edits list just the owner). (3) Add/flatten carry a soil budget: over-budget air->solid flips are skipped, so soil can never go negative. (4) Flatten captures its plane on the first held frame with valid aim (pressing F at the sky then swinging down starts the stroke); releasing clears it. (5) Edit versions prune once applied with nothing outstanding; drain sorts on the dirty set. (6) Collider rebuild state prunes on apply and on ring eviction. (7) Sim rejects out-of-range (6 m + radius) and foreign-planet strokes; all terminal paths emit `actionApplied`. (8) Idle frames skip the fallback march/normal (collider ray only). (9) Edit buffers transfer (zero-copy) to workers. (10) Buried camera reports a t = 0 hit instead of losing aim.

### FIX tool aim origin (done)
Reported: terrain could not be edited, aiming down did nothing. Root cause: the aim ray started at the orbit camera (2–8 m behind the player) with the 6 m budget measured from there, so the zoom distance ate the reach — at far zoom nothing was editable, and ground at the feet was out of range. Fix: the ray starts at the astronaut's head and continues along the camera view direction, so the 6 m budget is measured from the player (matching the sim-side range check); camera position only sets the direction. Regression test in `tests/player/toolAim.test.ts` (zoomed-out orbit geometry: hits from the head, misses from the camera). 150 tests pass.
