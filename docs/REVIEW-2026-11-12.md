## Critical

### 1. Loose items fall through the planet when their ground unloads [checked]
- `src/sim/systems/items.ts:57-83` integrates gravity for every loose item every tick.
- Terrain trimeshes only exist within `COLLIDER_RANGE_M` (48 m) plus one chunk of the player. `TerrainColliders.collectGarbage` drops the rest.
- Scenario: drop an item and walk ~100 m away. Or die off-network: `die()` in `src/sim/systems/oxygen.ts` drops the pack, then teleports the player to the habitat. Next tick the colliders under the items are gone and the items fall toward the core.
- This breaks the PROJECT.md rule "backpack items drop where you died, marker shows them".
- Fix:
  - Pass `TerrainColliders` (or a `groundReady(planet, pos)` callback) into `ItemsOptions`.
  - While an item's containing LOD0 chunk is not `'ready'`, skip gravity, zero its linear velocity, and make it a sleeping or kinematic body. This mirrors how `src/sim/physics/system.ts` freezes the player.
  - Without colliders, items far from the player simply stay frozen. That is acceptable.
- Test: an item with no loaded collider keeps its position over 60 ticks.

## Major

### 2. Oxygen canister is consumed while refilling on the network [checked]
- `src/sim/systems/oxygen.ts:176` checks `oxygen.value <= OXYGEN_CANISTER_THRESHOLD && consumeCanister(...)` on every branch, including the on-network refill branch.
- Scenario: arrive at the habitat with O2 = 15 carrying a canister. The first refill tick gives about 15.67, which is still at or below 20, so the canister is burned.
- Fix: compute `onNetwork` once; only auto-fire the canister when not on the network.
- Test: on-network player at 15 O2 with a canister keeps the canister.

### 3. Node identity shifts after terrain edits [checked]
- `src/sim/systems/nodes.ts:96-117` re-seats every node in an edited chunk by re-running `nodesForChunk` against the edited density field.
- `src/sim/nodes.ts` uses one sequential `createRng` per chunk (line ~226). `findSurfaceSpot` and `findCaveSpot` consume a variable number of draws depending on density, so every later draw shifts.
- IDs are index-based (`nodeIdFor(..., index)`).
- Effect: after a dig, `node_..._1` can be a different resource at a different spot. It inherits stashed `nodeCharges`, or is skipped forever by `depletedNodes`. This contradicts the M07 decision "same seed + chunk always addresses the same deposit".
- Fix:
  - Derive one rng per (chunk, index), e.g. `createRng(\`${seed}:${planet.seed}:${key}:${i}\`)`, so draws never cascade.
  - Decide spot and resource from the BASE (unedited) density.
  - Use the edited field only to re-seat the position onto the current surface, or to hide a node whose ground was dug away.
- Test: the same chunk before and after an unrelated nearby dig yields the same id → resource mapping.

### 4. An edit that empties a chunk leaves the old mesh visible [checked]
- `src/terrain/chunkManager.ts:326-327`: on `item.result.empty` the code only calls `this.sink.markEmpty(key)`.
- `src/render/chunkMeshes.ts:67`: `markEmpty` is a no-op when a mesh exists, and nothing removes the mesh.
- Scenario: dig away a small isolated bump. Its mesh stays forever while the chunk is desired.
- Fix: in the empty branch, if `item.isEdit` (or a mesh exists), call `this.sink.remove(item.key)` before `markEmpty`.
- Test: a chunkManager test with a fake sink where an edit job returns empty for a meshed key, and the mesh is removed.

### 5. Worker retry re-sends detached edit buffers, so the job never settles [checked]
- `src/terrain/workerPool.ts:67-68` stores `{ ...request }` (shallow). `pump()` transfers `edits.indices.buffer` and `edits.values.buffer`, which detaches them.
- `failWorker()` re-queues the same request. The retry's `postMessage` throws `DataCloneError` inside `pump()`. The worker was already popped from `idle`, so it is lost, and the promise never resolves or rejects.
- `ChunkManager.inflight` and the `EditRemesher` refcount stay set, so that chunk never remeshes again.
- The same pattern is in `src/terrain/colliderPool.ts`.
- Fix:
  - Transfer copies (`indices.slice()`, `values.slice()`) and keep the originals for retry.
  - Wrap `postMessage` in try/catch: on failure, reject that job, return the worker to `idle`, and keep pumping.
- Test: inject a worker fake that errors once on an edit job; the promise must settle (resolve on retry).

### 6. Quit to menu loses unsaved progress; "Saved!" can lie [checked]
- `src/main.ts:49-53`: `onQuitToMenu` stops autosave without saving, so up to 60 s of progress is lost.
- `src/ui/menu.ts:75-77` shows "Saved!" regardless of the result. `storeSave` in `src/save/storage.ts` swallows errors.
- Fix:
  - Await `storeSave(game.snapshot())` before `stopSession()` on quit.
  - Make `storeSave` return `Promise<boolean>`.
  - Have the menu show "Saved!" or "Save failed".

### 7. Cavern-room density discontinuity at each floor wrap [measured]
- `src/terrain/density.ts:137` sets `roomU = dd - idx * pitch`, so `u` resets at each floor top. The room term (around lines 199-205) jumps there.
- Probe on Sela, seed 1337, 400 rays at 0.02 m steps: 313 jumps >1.5 at the wrap phase (max 17.15, 107 sign changes). There are zero with caverns disabled.
- Effect: flat phantom ceilings and planar surfaces inside cavern floors.
- Fix: make the room term continuous across the wrap, e.g. evaluate against the nearest room so the wrap sits mid-slab where the term is strongly positive on both sides.
- Test: sample along radial rays and assert no density jump larger than (step × max gradient) at wrap planes. Keep the existing cavern tests green.

## Minor

8. **`src/game/Game.ts` is 407 lines** (hard rule 9). Line 218 crams two statements onto one line. Split, for example the per-frame entity/HUD block or `toggleFly`, into `src/game/`.
9. **`window.__corelight_all`** (`src/game/debugHandle.ts:130`) keeps every past session's `World` alive after Quit → New game. Keep only the current handle (or cap the array), and clear it in `Game.stop()`. The `gameId` comment says "random" but it is a counter.
10. **Input edges queued during pause fire on resume.** Q in the pause menu drops an item on Resume. The fly camera also moves while paused (`flyCamera.update` sits outside the pause gate). Fix: `Game.setPaused(true)` disables input (which clears the queues) and skips the fly-camera update.
11. **`die()` does not reset motion state** (`src/sim/systems/oxygen.ts:86`). It should reset velocity, grounded, input, embedded/escape state the way `playerTeleport` does. It also always uses `habitatsOn(...)[0]`; PROJECT.md says respawn at the last visited habitat (latent while only one exists).
12. **Item spawn points can be inside terrain** [likely].
    - Drop: `src/sim/actions.ts:326` uses `forward*1.5 + up*0.5`. Looking straight down puts it ~1 m underground.
    - Mined items: `actions.ts:362` offsets along radial `up`, so drops from ceiling nodes land inside rock.
    - Fix: drop with a yaw-leveled forward; offset mined items along the node's own normal (its rotation's +Y).
13. **Missing sim-side input validation.**
    - `terrainEdit` only rejects `radius <= 0` (`actions.ts:157`); clamp to `TOOL_MIN_RADIUS..TOOL_MAX_RADIUS`.
    - `playerInput` lets NaN through `clampAxis` (`actions.ts:51`); reject non-finite values.
    - `deserializeEntity` doesn't validate `components` (`src/save/serialize.ts:169`).
    - A NaN position serializes as null and then makes the save load as "corrupt". Refuse to store a snapshot whose positions are non-finite.
14. **Edited-field mismatch** [likely].
    - `TerrainEdits.deltaAt` uses `Math.round` (nearest sample, `src/terrain/edits.ts:251`), while meshes interpolate. That gives up to 0.32 density error after a dig in the field used by aim, tethers, nodes and the burial safety. Fix: trilinear interpolation of the 8 neighbouring deltas.
    - `src/terrain/editDeltas.ts:53` clips the LOD1 window `hi` at +66, so border sample 34 is only partly averaged.
15. **Per-frame churn.**
    - `src/render/views/tetherView.ts` disposes and rebuilds every cable geometry each frame; only rebuild when tip positions change.
    - Items, nodes and item lights allocate sets, arrays and sorts per frame.
    - F5 bounds call `chunks.boxes()` and sort each frame; gate on a version counter.
    - The tether system sorts and joins relay ids every tick, and oxygen scans all entities twice per player per tick.
16. **Small items:**
    - Horizontal wheel (`deltaY === 0`) zooms, changes fly speed and grows the brush; return early.
    - `ChunkBounds` has no `dispose()`.
    - Ground items are not interpolated (they step at 30 Hz).
    - `src/render/views/nodeView.ts:50` hardcodes `'lumen_crystal'`/`'research_sample'`; add an emits-light field in `items.json` (hard rule 8).
    - `terrainEdited` subscriptions in `tethers.ts`/`systems/nodes.ts` are never unsubscribed.
17. **Design question (do not change without the human):** mining takes one charge per dig stroke at 10 strokes/s, so a 5-charge node empties in ~0.5 s.
